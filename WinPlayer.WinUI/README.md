# WinPlayer.WinUI

WinPlayer.WinUI 是一个基于 **WinUI 3** 和 Windows 原生 `MediaPlayer` 的桌面媒体播放器。项目采用 MVVM 组织主要播放逻辑，界面以视频画面为背景，标题栏、媒体文件夹、播放列表和控制栏以悬浮毛玻璃面板呈现。

> 本文是**完整使用说明**。仓库首页概览见 [`../README.md`](../README.md)；
> 开发环境、代码风格与提交约定见 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)；
> 普通 / 隐私双模式隔离的设计见 [`docs/双模式隔离-开发方案.md`](docs/双模式隔离-开发方案.md)；
> 图标与图片资源说明见 [`docs/Images资源说明.md`](docs/Images资源说明.md)。

## 主要功能

- 播放常见视频和音频文件
- 播放、暂停、上一项、下一项、快进和快退
- 拖动进度条定位播放位置
- 鼠标滚轮调整音量，支持静音和新媒体音量渐入
- 全屏播放，以及单击、双击播放区域的快捷操作
- 全屏时自动隐藏鼠标指针（用透明光标替换全部系统光标形状），指针移出窗口时自动还原
- 左侧媒体文件夹树和右侧播放列表
- 拖入媒体文件后添加到播放列表首项并立即播放
- 拖入文件夹后异步扫描媒体文件，避免阻塞界面
- 字幕轨道和音频轨道检测、菜单展示与切换
- 加载外挂字幕文件（`.srt`、`.ass`、`.ssa`、`.vtt`、`.ttml`、`.sup`、`.sub`）
- 可拖动设置片头结束位置和片尾开始位置
- 自动跳过片头/片尾
- 保存和恢复播放位置、播放列表、媒体文件夹列表及窗口位置
- 侧边栏宽度调整、独立显示和自动隐藏动画
- 底部控制栏自动隐藏或固定显示
- 可配置单例运行；后续启动参数会转发给已有窗口
- 命令行隐私播放：由调用方传入参数，本次打开的文件照常保存播放位置但不参与下一次启动的自动播放
- 操作成功或失败时显示状态提示
- 基于 Win2D 的播放区域毛玻璃效果

支持的扩展名：

`.avi`、`.mp4`、`.mkv`、`.iso`、`.wmv`、`.vob`、`.mpg`、`.mpeg`、`.rmvb`、`.rm`、`.dat`、`.mov`、`.m4v`、`.webm`、`.ts`、`.mts`、`.m2ts`、`.mp3`、`.m4a`、`.wav`、`.flac`、`.ape`、`.aac`、`.ogg`。

> 实际解码能力取决于 Windows 当前安装的媒体编解码器。扩展名受到支持并不代表系统一定能够解码该文件中的视频、音频或字幕编码。

## 启动参数

可以将一个或多个媒体文件路径作为命令行参数传入：

```powershell
WinPlayer.WinUI.exe "D:\Media\Example.mkv"
```

多个文件：

```powershell
WinPlayer.WinUI.exe "D:\Media\Episode01.mkv" "D:\Media\Episode02.mkv"
```

路径包含空格时必须使用双引号。启用“单例运行”后，再次执行命令会激活现有窗口，并把文件参数发送给现有播放器实例。

### 参数前缀

除直接给出路径外，还可以用前缀显式指定本次打开的方式（前缀不区分大小写）：

| 前缀 | 作用 |
| --- | --- |
| `Play:` | 该文件加入播放列表，并作为本次启动的自动播放目标 |
| `Folder:` | 该路径作为媒体文件夹加入左侧文件夹列表（不改变自动播放目标） |
| `Privacy:` | 等价于 `Play:`，同时把整个进程标记为隐私模式（见下节） |
| `Records:` | 兼容旧调用方的占位前缀，当前被忽略，不加载任何内容 |

```powershell
WinPlayer.WinUI.exe "Play:D:\Media\Movie.mkv"
WinPlayer.WinUI.exe "Folder:D:\Media"
```

不带前缀的裸路径按 `Play:` 处理，但只有**第一个**裸路径会成为自动播放目标。
纯开关参数（如 `--privacy`）本身不打开任何内容；无法加载的路径会记入日志并跳过，
不影响其余参数的加载。

### 隐私播放（隐私模式）

隐私模式用于“要接着看，但不想留下痕迹”的场景：**它是一整套独立会话**，不只是隐藏某一条记录。
播放位置照常保存，只是存在隐私模式自己的记录文件里，之后用隐私模式再次打开即可续播。

**是否采用隐私模式完全由调用方在启动时决定**（播放器不保存任何“隐私开关”）：

```powershell
# 开关形式：本次进程即为隐私模式
WinPlayer.WinUI.exe --privacy "D:\Media\Example.mkv"

# 前缀形式：等价于 Play:（进程同样是隐私模式）
WinPlayer.WinUI.exe "Privacy:D:\Media\Example.mkv"
```

行为说明：

- `--privacy` 兼容 `-privacy`、`/privacy`，大小写不敏感；该参数决定**整个进程**的模式。
- **两种模式数据完全隔离**：隐私模式只写 `history.b.json` 与 `settings.b.json`；普通记录
  `playback-history.json`、普通设置 `settings.json`、播放列表 `playlist.json` 一概不写。
- **不改动播放列表与媒体文件夹列表**：隐私打开只播放指定的那个文件，不把它加入播放列表
  （列表里也不显示选中项），退出时也不写回列表文件。
- **普通模式永远看不到隐私记录**：隐私播放过的文件不会成为普通模式启动时的自动播放目标，
  列表里也不会显示它的续播位置。
- 隐私模式**可以续上普通模式看过的进度**（本区优先、未命中回退只读普通记录），反向不可见。
- **两种模式可同时运行**：各自独立的单例与激活通道——隐私启动不会挤进正在运行的普通窗口
  （会另开一个隐私窗口），反之亦然。
- 隐私窗口使用不同的窗口/任务栏图标（`player.b.ico`）与独立的任务栏应用标识，
  任务栏显示为两个按钮；隐私模式不修改注册表，也不刷新文件关联命令。选项窗口中的
  「注册关联 / 移除关联」在隐私模式下会被直接拒绝并给出提示，因为这两项操作都会写入 `HKCU`。
- 隐私模式的日志为 `Logs\winplayer.b.log`，且不记录媒体完整路径。
- 参数必须和至少一个媒体文件路径同时给出；只有开关而没有可用文件时不播放任何内容。
- 系统文件关联的“双击打开”无法附加该参数（系统只传文件路径），需要用快捷方式、命令行或“运行”对话框指定参数。
- **隔离不等于加密**：记录与设置都是明文 JSON，能访问这些文件的人就能看到内容。

## 选项

选项窗口（**独立窗口**，标题与底部会标明当前模式及设置文件）目前提供以下设置：

- 主题：跟随系统 / 浅色 / 深色
- 自动播放和自动进入全屏
- 单击播放区域切换播放/暂停的开关
- HDR/杜比视界直通呈现（实验）：关闭帧服务器自绘，把画面交回系统合成器输出
- libmpv 杜比视界引擎：用 libmpv（软件渲染 API + libplacebo 滤镜链）播放系统媒体框架无法正确呈现的内容
- 外部播放器路径：把系统无法呈现的杜比视界内容交给 mpv/完美解码等播放器
- 本项目字幕开关：关闭后本程序不再绘制自己的字幕层（字幕交给播放引擎/系统），
  适合杜比视界经 libmpv 引擎播放时避免与片源字幕叠成两行
- 字幕字体、字号与底部偏移
- 默认音量
- 新媒体音量渐入开关及过渡时间
- 快进/快退间隔
- 片头和片尾跳过位置
- 底部控制栏固定显示
- 窗口总在最前
- 控制层自动隐藏延迟及动画时长
- 左、右侧栏宽度与侧栏自动显示
- 毛玻璃模糊强度和色调不透明度
- 单例运行
- 文件关联注册与移除、系统默认应用入口
- 播放位置保存、恢复，历史记录保留天数与记录条数上限
- 记录管理：清空当前模式的记录 / 清空两种模式的记录（见“本地数据”）

窗口顶部导航分为“播放 / 界面 / 记录与启动 / 诊断日志”四页（“诊断日志”页内的标题为“诊断”）；
设置窗口独立于主窗口，主窗口缩到很小时也不会把设置项裁掉（内容区可滚动）。
设置窗口同时只会存在一个，并随主窗口一起关闭。

## 文件关联

在“选项 → 记录与启动”中可以注册或移除文件关联：

- 对话框中列出全部受支持的扩展名，可自行勾选要关联的子集（支持全选/清空），选择会随选项保存；“注册关联”按当前勾选结果写入，取消勾选的扩展名会同步移除。
- 注册会把选中的扩展名写入当前用户的“打开方式”候选列表，不会修改各扩展名当前的默认程序。
- 要让双击文件直接打开本播放器，需要在“系统默认应用”设置中按文件类型选择本播放器；也可以对单个文件右键“打开方式 → 选择其他应用”并勾选始终使用。
- 注册后程序被移动到其他目录时，下次启动会自动把注册表中的命令更新为新路径。
- 关联信息保存在当前用户注册表（`HKCU\Software\Classes`），无需管理员权限；“移除关联”只删除本程序写入的内容。

## 本地数据

用户设置和播放状态保存在：

```text
%LOCALAPPDATA%\WinPlayer.WinUI\
```

程序有两种运行模式（普通模式 / 隐私模式，由启动参数决定），**两者数据完全隔离**：
普通模式的文件没有后缀，隐私模式的文件带 `.b` 后缀。

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 普通模式：播放器选项、音量、侧栏宽度和窗口位置等 |
| `playlist.json` | 播放列表及左侧媒体文件夹列表（**两种模式共用；隐私模式只读**） |
| `playback-history.json` | 普通模式：各媒体文件的播放位置和更新时间 |
| `settings.b.json` | 隐私模式：独立的播放器选项与窗口状态（首次使用由普通设置初始化） |
| `history.b.json` | 隐私模式：独立的播放记录 |
| `Logs\winplayer.log` / `Logs\winplayer.b.log` | 各自的诊断日志（JSON Lines 格式），单个文件超过 5 MB 时轮换为同模式的 `winplayer.previous.log`；隐私日志不记录媒体完整路径 |
| `startup-error.log` / `startup-error.b.log` | 各自的未处理 WinUI 启动异常信息 |

隔离规则：

- 隐私模式**只写** `settings.b.json` 与 `history.b.json`：不写普通记录、不改动播放列表与
  媒体文件夹列表、不修改注册表，也不刷新文件关联命令。
- 隐私模式的续播位置以本区优先，读不到时回退读取普通记录（只读），因此隐私打开也能续上
  之前普通看过的进度；反向不可见——普通模式看不到隐私记录，其自动播放也绝不会选中隐私
  播放过的文件。
- 两种模式可以**同时运行**（各自独立的单例与激活通道），窗口与任务栏图标不同
  （`player.ico` / `player.b.ico`），任务栏显示为两个独立按钮。
- **隔离不等于加密**：以上文件都是明文 JSON，能读到文件的人就能看到记录内容。

清空记录（位置：**设置窗口 → 记录与启动 → 记录管理**）：

- **清空当前模式的记录**：只清当前模式自己的记录文件，另一种模式不受影响。
- **清空两种模式的记录**：一次清掉两个记录文件（设置与播放列表不动）。
- 两项都会先弹出确认，两个记录文件里的文件路径也一并清除。

如需恢复默认配置，请先退出播放器，再备份或删除该目录中的对应 JSON 文件。

## 构建

在项目目录执行：

```powershell
dotnet restore
dotnet build WinPlayer.WinUI.csproj -c Debug -p:Platform=x64
```

也可以使用 Visual Studio 打开 `WinPlayer.WinUI.csproj`，选择与电脑架构一致的平台后运行：

- 普通 Intel/AMD 电脑：`x64`
- 32 位 Windows：`x86`
- Windows on ARM 设备：`ARM64`

不要混用配置平台和目标运行时，例如 `Release | ARM64` 必须对应 `win-arm64`。

## 发布

项目已经提供以下发布配置：

```text
Properties/PublishProfiles/win-x86.pubxml
Properties/PublishProfiles/win-x64.pubxml
Properties/PublishProfiles/win-arm64.pubxml
```

发布 x64 版本：

```powershell
dotnet publish WinPlayer.WinUI.csproj -c Release -p:Platform=x64 -r win-x64 --self-contained true
```

发布后必须保留整个 `publish` 目录，不能只复制 EXE。WinUI、.NET 运行时、PRI/XBF 资源和图标等文件都是程序运行所需内容。

当前项目配置为：

- 自包含部署
- 不生成单文件
- 不启用裁剪
- 不启用 ReadyToRun
- 发布后补充复制 `App.xbf`、`MainWindow.xbf`、`SettingsWindow.xbf` 和 `WinPlayer.WinUI.pri`

这些设置用于降低 WinUI 未打包发布时因运行时、反射元数据或 XAML/PRI 资源缺失而无法启动的风险。

## 故障排查

### 发布程序提示“此应用无法在你的电脑上运行”

检查发布架构是否与目标电脑一致。大多数 Intel/AMD Windows 电脑应使用 `Release | x64` 和 `win-x64`，不能运行 `win-arm64` 版本。

### 发布后双击没有反应

1. 确认复制的是完整发布目录。
2. 检查 `WinPlayer.WinUI.pri`、`App.xbf`、`MainWindow.xbf` 和 `Images\player.ico` 是否存在。
3. 查看 `%LOCALAPPDATA%\WinPlayer.WinUI\startup-error.log`。
4. 确认没有开启裁剪或单文件发布。

### 某些视频、字幕或音轨无法使用

播放器使用 Windows 原生媒体框架，支持情况取决于系统编解码器、媒体容器以及轨道格式。可先使用系统“媒体播放器”验证同一文件是否能够正常解码。

### 杜比视界视频发绿/发紫，或不确定是否进入 HDR

杜比视界内容分为几种规格，播放表现差异很大：

- **Profile 5**：单层 IPT 编码，没有 HDR10 兼容基础层。播放器若不处理 RPU 元数据，就会把 IPT 当成普通 YCbCr 显示，表现为发绿/发紫。
- **Profile 8**：基础层兼容 HDR10/HLG，即使不处理 RPU 也能按 HDR10 正确显示。
- **Profile 7**：双层（含增强层），PC 上的播放器普遍不处理增强层。

排查方式：

1. 打开“选项 → 诊断”，点击“HDR / 杜比诊断”按钮：结果会直接显示在按钮右侧，
   同时写入诊断日志（`%LOCALAPPDATA%\WinPlayer.WinUI\Logs\winplayer.log`）中的
   `HdrDiagnostics` 与 `DolbyVisionProbe` 记录。诊断会给出：当前是自绘还是直通呈现、系统给出的输出降级原因、
   显示器的高级颜色种类与峰值亮度、视频轨道编码信息，以及文件中的杜比视界标记与推测 Profile。
2. 在“选项 → HDR 与杜比视界”中把“直通呈现”切换为“直通”，让系统合成器负责输出，
   再对比画面与日志中的降级原因——这是判断“能否进入 HDR”的最直接方式。
3. 若系统侧同样异常，请确认已安装 HEVC 视频扩展与杜比视界扩展（Microsoft Store）。
   本程序的自绘路径（默认）把帧服务器输出绘制到 8 位表面，HDR 元数据与杜比视界信息在这一步会丢失，
   因此直通呈现才是 HDR/杜比内容的首选路径（代价是毛玻璃采样不生效）。
4. **若直通呈现下画面依旧发绿/发紫**：说明系统媒体框架没有处理杜比视界的 IPT/RPU 数据
   （Profile 5 单层 IPT 一定会这样，Profile 8 则退化为按 HDR10 基础层显示）。
   此时开启内置的 **libmpv 杜比视界引擎**（选项 → HDR 与杜比视界 → libmpv 杜比视界引擎，
   或播放区域右键菜单中的「打开杜比引擎」）：它用 libmpv 的软件渲染 API 输出画面，并由
   libplacebo 完成杜比视界重塑与色调映射，颜色正确。
   - 需要 `libmpv-2.dll`。查找顺序为：
     ① 环境变量 `WINPLAYER_LIBMPV`；
     ② 程序目录下的 `libmpv-2.dll`、`libmpv\libmpv-2.dll`、`runtimes\win-x64\native\libmpv-2.dll`；
     ③ 从程序目录逐级向上查找 `.tools\mpv-dev\libmpv-2.dll` 或 `mpv-dev\libmpv-2.dll`
     （便于开发时免去手工复制）。
   - 也可以在播放区域右键菜单里勾选/取消「打开杜比引擎」即时切换。
   - 该模式下画面由本程序画布呈现，因此“直通呈现”开关不再影响画面路径。
   - 仓库**不包含** `libmpv-2.dll`，需自行获取，并遵守其 LGPL/GPL 许可条款。
   - 选项中的“外部播放器路径”用于登记一个支持杜比视界的外部播放器
     （例如完美解码中的 `C:\Program Files\Pure Codec\x64\PotPlayerMini64.exe`，或自行安装的 mpv）。
     该入口目前**未挂到界面上**（播放区域右键菜单中的对应项已注释停用），
     需要外部播放时请直接用该播放器打开文件。
   - 参考实测结果（同一帧、同一台机器）：做杜比视界重塑的 libplacebo 管线颜色正常；
     不处理杜比视界的管线（系统媒体框架、`mpv --vo=gpu`）画面明显发绿/发紫。
5. **出现两行字幕（片源字幕与本程序字幕重合）**：该剧集片源本身带两条 SRT 字幕轨
   （简体 / 繁体）；同一句话的简繁写法相同时，两条轨都渲染就会看起来像"同一句写了两遍"。
   处理方式：
   - 使用 libmpv 杜比视界引擎时，字幕**完全由引擎渲染**，本程序不再绘制自己的字幕层，
     引擎也只渲染一条字幕轨（副字幕已关闭）；
   - 顶栏**字幕菜单**在引擎模式下会列出引擎的字幕轨（如 Simplified / Traditional Chinese）
     与“关闭字幕”，选一条或直接关闭即可；
   - 需要强制使用本程序自己的字幕渲染时，可用字幕菜单顶部的“本项目字幕”开关
     （引擎模式下本程序字幕自动隐藏，所以该开关主要作用于系统媒体框架播放的场景）。
